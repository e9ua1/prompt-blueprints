# Mental Models Distilled 레포지토리 제작 프롬프트

나는 "Mental Models Distilled" 레포지토리를 만들려고 해.
세상을 읽는 렌즈들 — 2차 효과가 왜 1차 효과를 자주 뒤집는지, 인버전이 왜 더 쉬운 길인지, 멱법칙 세계와 정규분포 세계에서 전략이 어떻게 정반대가 되는지, 병목 하나가 시스템 전체를 어떻게 지배하는지를 메커니즘까지 해부하는 레포야.
"모델 100개를 수집하는 것"과 "문제 앞에서 맞는 렌즈 3개를 꺼내 겹쳐 보는 것"의 차이를 만드는 레포다.

## 📋 프로젝트 목표

**컨셉**: "멘탈 모델을 아는 것과, 어떤 문제에 어떤 모델을 적용하고 어디서 모델이 깨지는지 아는 것은 다르다"

**핵심 차별화**:
1. 수집이 아니라 적용 조건 — 모델마다 "작동하는 세계의 조건"과 "깨지는 경계"를 명시 (이 레포의 존재 이유)
2. 분포 세계관의 분기 — 정규분포 세계(평균 회귀·분산)와 멱법칙 세계(극단 추구·집중)에서 최적 전략이 정반대
3. 격자(latticework) — 모델 하나는 망치, 여러 모델의 교차 검증이 판단. 충돌할 때의 우선순위 규칙까지
4. 모델≠현실 — 지도-영토 문제를 장식이 아니라 운영 원칙으로: 모델 갱신 트리거를 정의

**타겟 독자**:
- 멘탈 모델 리스트를 북마크했지만 결정이 안 바뀐 사람
- 1차 효과(가격 인하→판매 증가)만 보고 2차 효과(가격 전쟁)에 당하는 창업가
- 모든 문제를 한 가지 렌즈(예: 효율)로만 보는 개발자
- "평균적으로 좋은 선택"이 멱법칙 세계에서 패배 전략임을 모르는 사람
- `decision-theory`·`cognitive-bias`와 묶어 사고 도구 세트를 완성하려는 독자

## 🔗 레포 연결

**⬆️ 선행**: 없음 — Layer 0의 골격. 단, `probabilistic-thinking-distilled`(분포 직관)과 병행하면 좋다.
**🤝 시너지**: `decision-theory-distilled`(인버전·2차 효과는 대안 생성과 결과 예측 도구), `cognitive-bias-distilled`(모델은 편향의 해독제이자 새 편향의 원천).
**🧬 수렴**: L5 전체 — `incentives-everywhere`(인센티브 렌즈), `feedback-loops-everywhere`(피드백 렌즈), `compounding-everywhere`(복리 렌즈), `leverage-everywhere`(병목·지렛대 렌즈). 이 레포는 L5 네 레포의 원료 창고다.

## 🎯 1단계: 전체 구조 설계

### Chapter 1: 모델이라는 도구 (5개 문서)
- 지도 ≠ 영토 — 모델은 압축, 압축은 손실, 손실의 위치를 아는 것이 실력
- 모델의 효용 함수 — 좋은 모델의 기준: 예측력×적용 범위×비용, 단순함의 가치
- 격자식 사고 — Munger의 latticework, 한 모델 의존이 만드는 망치-못 문제
- 모델 선택 절차 — 문제 유형→후보 렌즈→교차 검증, 적용 조건 매칭
- 모델 갱신 — 강한 의견·약한 고수, 모델을 버리는 트리거의 사전 정의

### Chapter 2: 인과와 효과의 모델 (6개 문서)
- 1차/2차 효과 — "그 다음에 무슨 일이?"를 한 번 더, 2차가 1차를 뒤집는 조건
- 인버전 — 성공 조건 대신 실패 조건 제거, 왜 거꾸로가 더 쉬운가
- 한계 사고 — 평균이 아니라 다음 한 단위, 한계 비용·한계 효용의 렌즈
- 기회비용 — 모든 선택의 가격은 차선책, 보이지 않는 비용 보이게 하기
- 인센티브 렌즈 — 행동을 바꾸려면 구조를 봐라(L3 incentive-design 예고)
- 피드백 루프 — 강화·균형 루프, 결과가 원인이 되는 구조(L5 예고)

### Chapter 3: 분포와 스케일의 모델 (5개 문서)
- 두 개의 세계 — 정규분포(키·오차) vs 멱법칙(부·도시·히트작), 생성 메커니즘의 차이
- 80/20과 그 너머 — 파레토의 재귀성(상위 20%의 20%), 노력 배분의 함정
- 비선형과 임계점 — 선형 외삽이 깨지는 곳, 상전이·티핑 포인트
- 평균의 함정 — 평균 수심 1m 강에 빠져 죽는 이유, 분포 전체를 보기
- 전략의 분기 — 정규 세계: 일관성·분산 / 멱법칙 세계: 극단 노출·집중(창업이 후자인 이유)

### Chapter 4: 제약과 병목의 모델 (5개 문서)
- 병목의 지배 — 시스템 처리량 = 병목의 처리량, 비병목 개선이 무의미한 증명(TOC)
- 최소율의 법칙 — 리비히의 통, 성장의 제약 인자 식별
- 병목 식별 절차 — 어디서 일이 쌓이는가, 재고·대기열이 가리키는 곳
- 지렛대 포인트 — 같은 힘, 다른 위치, 시스템에서 개입 효과가 큰 지점(Meadows)
- 제약의 이동 — 병목을 풀면 병목이 이동한다, 연속 추적의 운영

### Chapter 5: 시스템의 모델 (5개 문서)
- 스톡과 플로우 — 욕조 모델, 잔고와 흐름의 혼동이 만드는 오판
- 균형과 항상성 — 시스템이 저항하는 이유, 정책 저항(밀어내면 되민다)
- 지연의 효과 — 원인과 결과 사이의 시차, 지연이 만드는 진동(과잉 보정)
- 창발 — 부분에 없는 성질이 전체에서, 환원이 실패하는 지점
- 측정의 역습 — 지표가 목표가 되면 좋은 지표이길 멈춘다(L3 Goodhart 예고)

### Chapter 6: 인식의 모델 (5개 문서)
- 능력 범위 — Circle of Competence, 경계 안과 밖에서 다른 행동 규칙
- 오캄과 한론 — 단순한 설명 우선·악의 가정 금지, 두 면도날의 적용 한계
- 체스터튼의 울타리 — 이유를 모르는 것을 제거하지 마라, 레거시의 재해석
- 관점 획득 — 입장 바꾸기·시간 늘리기(10/10/10)·외부인 시점, 렌즈 전환의 기술
- 확신의 보정 — 모델이 잘 맞을 때가 가장 위험한 이유(과적합·체제 변화)

### Chapter 7: 격자 짜기 실전 (5개 문서)
- 모델 조합 — 한 문제에 렌즈 3개 겹치기, 교차 검증으로 맹점 줄이기
- 모델 충돌 — 렌즈끼리 반대 결론일 때, 적용 조건으로 판정하는 절차
- 창업 문제에 격자 적용 — 가격 결정 하나를 6개 렌즈로 통과시키는 워크스루
- 안티 라이브러리 — 수집욕과의 싸움, 모델 5개를 깊게가 100개 목록을 이긴다
- 종합 — 실제 문제 하나를 격자 전체로 처리하는 통합 케이스

→ **총 36개 문서** 목표.

## 📄 문서 구조

각 문서 10섹션 (phronesis 표준):
1. **🎯 핵심 질문** — 이 문서가 바꾸려는 결정
2. **🌍 어디서 마주치나** — 사업·일상에서 이 원리가 작동하는 장면
3. **🔍 통념** — 흔한 오해, 그 오해가 비싼 이유
4. **⚙️ 메커니즘** — 왜 그렇게 작동하는가 (유도·1차 원리)
5. **📜 사례** — 실제 세계에서 검증된 기록
6. **🔨 반례** — 깨지는 조건, 경계는 어디인가
7. **🧬 횡단 연결** — 다른 레이어에서 반복되는 같은 구조
8. **⚖️ 트레이드오프** — 이 원리를 적용하는 비용
9. **🧭 판단 규칙** — Principle → Boundary → Rule
10. **🤔 다음 질문** — 미해결 질문, 다음 문서 연결

이 레포에서 `🔨 반례`가 가장 중요하다 — 모델 레포의 실패 양식은 "만능 렌즈화"이므로, 모든 모델 문서는 *그 모델이 틀리는 실제 사례*를 최소 1개 포함한다. `🧬 횡단 연결`은 L1~L4에서 그 모델이 재등장하는 지점의 예고편.

## 🎨 스타일 가이드

1. **결정을 바꾸는가로 검증** — 결정을 바꾸지 못하는 지식은 잡학이다. "흥미로운 모델"은 탈락 기준
2. **적용 조건을 모델과 한 몸으로** — 모델 설명과 깨지는 조건을 분리하지 않는다
3. **반례에 살아남는가** — 모델이 실패한 실제 사례를 모델 성공 사례와 같은 비중으로
4. **수집 금지** — 유사 모델은 묶고, 결정을 못 바꾸는 모델은 버린다. 36개 문서에 모델 백과를 욱여넣지 않는다
5. **워크스루로 증명** — 격자 적용은 추상 설명이 아니라 실제 문제 1개의 단계별 통과로
6. 분포 분기·병목·피드백 루프는 다이어그램으로

## 🔬 검증 프로토콜

> 시뮬레이션 + 모델 실패 사례 수집 + 격자 워크스루.

```python
# 환경: Python 3 + numpy (모델의 수학적 골격 검증)

# 1) 두 분포 세계 생성 메커니즘
#    덧셈 과정(독립 요인 합) → 정규분포 수렴 (CLT 재현)
#    곱셈·선호적 연결 과정 → 멱법칙 생성 (Yule/Barabási 재현)
#    → "어떤 프로세스가 어떤 세계를 만드는가"를 코드로

# 2) 병목의 지배 (TOC)
#    5단계 파이프라인, 처리량 [10,10,3,10,10]/h 시뮬레이션
#    → 비병목 2배 개선: 처리량 변화 0 / 병목 2배: 전체 2배
#    → 재고(대기열)가 병목 앞에 쌓이는 패턴 관찰

# 3) 지연이 만드는 진동
#    온도 조절(지연 3틱) 피드백 시뮬레이션
#    → 지연 없으면 수렴, 지연 있으면 과잉 보정→진동 재현

# 4) 80/20의 재귀
#    파레토 분포 샘플 → 상위 20%가 80% 차지 확인
#    → 그 상위 안에서 다시 80/20 재현 (프랙탈성)

# 5) 모델 실패 사례 수집 (반례 데이터베이스)
#    각 모델당: 적용했다가 실패한 공개 사례 1건 이상
#    예: 오캄 적용 실패(단순한 설명이 틀린 의학 사례),
#        한계 사고 실패(임계점 무시), 인버전 실패(실패 회피만 하다 기회 상실)

# 6) 격자 워크스루
#    실제 결정 1건(예: 가격 인상)을
#    인센티브→2차 효과→탄력성→피드백→병목→기회비용 렌즈로 순차 통과
#    → 렌즈마다 결론 기록, 충돌 시 판정 근거 기록
```

## 💡 핵심 분석 대상

```
두 분포 세계의 전략 분기 (이 레포의 척추):
                정규분포 세계        멱법칙 세계
  생성 과정   │ 독립 요인의 합      │ 곱셈·복리·선호적 연결
  대표 영역   │ 키·제조 오차·시험   │ 부·스타트업·콘텐츠·도시
  극단값      │ 무시 가능           │ 전부를 결정
  최적 전략   │ 일관성·평균 개선    │ 극단 노출·집중·시도 횟수
  실패 양식   │ 분산 부족           │ 평균에 최적화
  → 자기 게임이 어느 세계인지 오판하면 전략 전체가 뒤집힌다

병목의 지배 (TOC):
  [10/h] → [10/h] → [3/h] → [10/h] → [10/h]
                      ↑
  시스템 처리량 = 3/h (병목이 전부)
  → 비병목 개선 = 비용만 발생, 재고만 증가
  → 개선 투자의 유일한 질문: "여기가 병목인가?"

2차 효과의 반전:
  1차: 가격 인하 → 판매량 증가 (+)
  2차: 경쟁사 추종 → 가격 전쟁 → 전원 마진 붕괴 (−−)
  3차: 저마진 체질화 → 품질 투자 불능 (−)
  → "그 다음에 무슨 일이 일어나나"를 멈추는 지점이 판단의 깊이

판단 규칙 예시 (Principle → Boundary → Rule):
  Principle : 시스템 개선 투자는 병목에만 집중한다
  Boundary  : 병목이 빠르게 이동하는 시스템(수요 변동 극심)이나
              병목이 외부(규제·플랫폼)에 있어 통제 불가능하면 무효
  Rule      : 개선안마다 "이게 병목 처리량을 올리나?"를 먼저 묻고,
              아니오면 보류한다. 병목을 풀었다면 즉시 다음 병목을
              재식별한다 — 어제의 정답이 오늘의 낭비가 된다
```

## 🎯 진행 방식
