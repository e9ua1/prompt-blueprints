# Decision Theory Distilled 레포지토리 제작 프롬프트

나는 "Decision Theory Distilled" 레포지토리를 만들려고 해.
좋은 결정과 좋은 결과가 왜 다른지 — 효용 곡선이 리스크 회피를 어떻게 만들어내는지, 가역/비가역이 결정 속도를 어떻게 결정해야 하는지, 옵션성이 왜 공짜에 가까운 비대칭인지를 끝까지 해부하는 레포야.
"고민을 오래 하는 것"과 "결정의 구조를 분해해 어디에 시간을 쓸지 아는 것"의 차이를 만드는 레포다.

## 📋 프로젝트 목표

**컨셉**: "결과로 결정을 평가하는 것과, 결정 시점의 정보로 결정의 질을 평가하는 것은 다르다"

**핵심 차별화**:
1. Resulting의 해체 — 결과≠결정의 질, 운과 실력의 분리가 가능한 조건과 불가능한 조건
2. 효용 곡률 — 리스크 회피는 성격이 아니라 한계효용 체감의 수학적 귀결
3. 결정의 두 종류 — 가역(Two-way Door)은 빠르게·위임, 비가역(One-way Door)은 느리게·집중. 이 분류 자체가 조직 설계
4. 옵션성 — 작은 고정 비용으로 큰 비대칭 페이오프를 사는 구조, 미루기·실험·계약 조항의 공통 수학

**타겟 독자**:
- 잘된 결정은 내 실력, 안 된 결정은 운 탓으로 복기하는 창업가
- 모든 결정에 같은 강도의 고민을 쏟아 속도가 죽는 사람
- 매몰비용 때문에 죽은 프로젝트를 못 접는 개발자
- "신중함"과 "정보 수집의 기댓값"을 구분 못 하는 사람
- `probabilistic-thinking`의 EV를 실제 결정 절차로 연결하려는 독자

## 🔗 레포 연결

**⬆️ 선행**: `probabilistic-thinking-distilled`(기댓값·분산·확률 추정이 입력값).

## 🎯 1단계: 전체 구조 설계

### Chapter 1: 결정의 해부 (5개 문서)
- 좋은 결정 ≠ 좋은 결과 — Resulting 오류, 포커에서 배우는 분리
- 결정의 구성요소 — 대안·정보·선호·불확실성, 어디가 부실한지 진단
- 결정의 질 평가 — 결과가 아니라 과정을 채점하는 기준
- 운과 실력의 비중 — 분리 가능 조건(반복·즉각 피드백), 사업은 어느 쪽인가
- 결정 분류학 — 크기×가역성×빈도 매트릭스, 분류가 절차를 정한다

### Chapter 2: 효용과 리스크 (5개 문서)
- 효용 곡선 — 돈≠효용, 한계효용 체감이 만드는 오목 곡선
- 리스크 회피의 수학 — 오목성→기대효용<효용(기댓값), 보험이 성립하는 이유
- 확실성 등가 — 불확실한 100억 vs 확실한 X억, X를 구하는 절차
- 리스크 프리미엄 — 회피의 가격, 누가 리스크를 사고 파는가
- 파산 회피 우선 원칙 — 효용 곡선의 왼쪽 끝(0)은 비대칭 절벽(prob 에르고딕성 연결)

### Chapter 3: 가역성과 옵션 (5개 문서)
- One-way vs Two-way Door — 베조스 분류, 가역성이 결정 속도를 정한다
- 70% 규칙 — 정보 70%에서 움직이는 근거, 기다림의 한계 비용
- 옵션성의 구조 — 작은 프리미엄·큰 비대칭, 실험·계약·미루기의 공통 수학
- 정보 수집의 가치 — 더 알아보기의 기댓값(VOI), 언제 그만 알아보나
- 비가역 결정 프로토콜 — 느리게·반대 의견·프리모텀, 되돌릴 수 없는 문 앞의 절차

### Chapter 4: 불확실성 하의 결정 (5개 문서)
- 리스크 vs 불확실성 — 확률을 아는 것과 모르는 것(Knight), 절차가 달라진다
- 후회 최소화 — minimax regret, 확률을 모를 때의 합리적 기준
- 강건한 결정 — 최적화 대신 "어느 시나리오에서도 죽지 않음"을 사는 법
- 시나리오 사고 — 점 예측 대신 분기, 각 분기에서의 행동을 미리 결정
- 프리모텀 — "이미 실패했다"에서 역산, 사전 부검의 실증 효과

### Chapter 5: 시간과 결정 (4개 문서)
- 할인과 시간 선호 — 미래 가치를 깎는 비율, 일관성 없는 할인의 비용
- 매몰비용과 한계 사고 — 이미 쓴 것은 변수가 아니다, 접는 결정의 수학
- 중단 규칙 — 비서 문제(37% 규칙), 탐색을 언제 멈추고 결정하나
- 장기 게임 — 반복 결정에서 단일 결정과 달라지는 것(평판·복리·학습)

### Chapter 6: 집단과 프로세스 (5개 문서)
- 결정 프로세스 설계 — 누가·언제·어떤 정보로, 절차가 품질을 만든다
- 집단 결정의 함정 — 집단사고·정보 폭포·서열 효과, 모이면 멍청해지는 메커니즘
- 반대 의견의 가치 — 레드팀·악마의 변호인, 반대를 제도화하는 법
- 결정 권한 배분 — 가역성 매트릭스로 위임 경계 긋기, 병목 제거
- 결정 일지와 사후 검토 — 시점의 정보로 기록, 결과 아닌 과정을 채점(prob 캘리브레이션 연결)

### Chapter 7: 실전 (5개 문서)
- 창업 결정 프레임워크 — 피벗·중단·확장을 가역성×EV×생존으로 처리
- 채용과 투자 결정 — 비가역에 가까운 결정의 절차, 거짓 양성/음성의 비대칭
- 흔한 결정 오류 종합 — resulting·분석 마비·디폴트 추종·타이밍 착각
- 결정 위생 — 노이즈 줄이기(독립 추정→취합), 판단의 재현성
- 종합 — 실제 결정 하나를 분류→효용→옵션→프로토콜로 끝까지 처리하는 통합 케이스

→ **총 34개 문서** 목표.

## 🎨 스타일 가이드

1. **결정을 바꾸는가로 검증** — 결정을 바꾸지 못하는 지식은 잡학이다
2. **결과가 아니라 시점 정보로 복기** — 모든 사례는 "그때 알 수 있었던 것"만으로 평가
3. **분류가 절차를 정한다** — 결정 유형(가역성×크기)마다 다른 프로토콜을 명시
4. **반례에 살아남는가** — 모든 규칙에 깨지는 조건 명시 (예: 70% 규칙은 경쟁 속도가 핵심 변수일 때만)
5. **수학은 페이오프 다이어그램으로** — 효용 곡선·옵션 비대칭은 그림이 본체
6. 결정 프로토콜은 표·체크리스트로 압축

## 🔬 검증 프로토콜

> 시뮬레이션 + 역사적 결정 복기 + 자기 결정 일지 운영.

```python
# 환경: Python 3 + numpy

# 1) Resulting 분리 실험
#    EV+ 전략 vs EV− 전략을 각 100회 시뮬레이션
#    → 단기(10회)에선 EV− 전략이 이기는 비율 측정
#    → "결과로 전략을 평가하면 몇 %나 속는가"를 수치화

# 2) 효용 곡선과 보험
#    log 효용 가정, 자산 1억인 사람의 화재(1%, −5천만) 리스크
#    → 기대손실 50만 vs 지불 의사 보험료 계산 → 보험사 마진의 정체

# 3) VOI(정보의 가치) 계산
#    추가 조사가 결정을 뒤집을 확률 × 뒤집었을 때의 이득 − 조사 비용
#    → "더 알아보기"의 기댓값이 음수가 되는 지점

# 4) 중단 규칙(비서 문제)
#    n=100 후보 시뮬레이션, 37% 관찰 후 최고 선택 전략
#    → 최적 후보를 뽑을 확률 ≈ 37% 재현, 다른 컷오프와 비교

# 5) 역사 복기 (시점 정보 기준)
#    공개된 기업 결정 1건(예: 넷플릭스 DVD 분사 시도)을
#    "당시 공개 정보만으로" 결정 품질 채점 → 결과와 분리해 평가

# 6) 결정 일지 (이 레포의 살아있는 검증)
#    실제 결정 10건: 시점 정보·확률·근거 기록 → 3개월 후 채점
```

## 💡 핵심 분석 대상

```
Resulting (결과로 결정을 평가하는 오류):
              좋은 결과        나쁜 결과
  좋은 결정 │ 실력 (정당)   │ 불운 ← 여기서 전략을 버리면 비싸다
  나쁜 결정 │ 요행 ← 여기서 전략을 믿으면 더 비싸다 │ 당연
  → 단기 표본에서 결과는 결정 품질의 약한 신호
  → 복기는 "그 시점에 알 수 있었던 것"만으로

가역성 매트릭스 (결정 속도의 근거):
                  영향 작음        영향 큼
  가역(2-way)  │ 즉시·위임      │ 빠르게·본인
  비가역(1-way)│ 빠르게·체크    │ 느리게·반대의견·프리모텀
  → 대부분 결정은 좌상단인데 우하단처럼 다룬다 (속도 손실)
  → 우하단을 좌상단처럼 다루면 회복 불가 (생존 손실)

옵션성의 비대칭 페이오프:
  가치
   ↑          ╱  ← 잘되면: 무제한 상방
   │        ╱
   ┼──────╱────────→ 상황
   │ ─────             ← 안되면: 프리미엄만 손실 (바닥 고정)
  → 실험·계약 조항·미루기·사이드 프로젝트의 공통 구조
  → 변동성이 클수록 옵션 가치 상승 (불확실성이 자산이 되는 유일한 곳)

판단 규칙 예시 (Principle → Boundary → Rule):
  Principle : 결정 속도는 신중함이 아니라 가역성이 정한다
  Boundary  : 되돌리는 비용이 추정 불가능하거나, 신뢰처럼
              한 번 깨지면 복구가 안 되는 자산이 걸린 경우엔 무효
  Rule      : 결정 전에 "이거 되돌리는 데 얼마·며칠?"부터 적는다.
              답이 명확하고 작으면 70% 정보에서 즉시 움직이고,
              답을 못 적겠으면 One-way Door 프로토콜로 보낸다
```
