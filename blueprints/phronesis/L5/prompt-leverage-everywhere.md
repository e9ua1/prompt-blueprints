# Leverage Everywhere 레포지토리 제작 프롬프트

나는 "Leverage Everywhere" 레포지토리를 만들려고 해.
IQ Phronesis Lab의 Synthesis 레이어 — **출력 = 입력 × 배율**이라는 구조의 수확. 재무 레버리지(L1), 고정비의 영업 레버리지, 코드와 미디어라는 무한 복제 레버리지, 옵션성이라는 비대칭 레버리지(L0), 가치사슬의 병목과 네트워크 급소라는 위치 레버리지(L3·L4) — 표면이 다른 이 모든 것이 같은 증폭 구조이며, **증폭은 방향을 가리지 않는다**(이익도 실수도)는 양면까지 끝까지 해부하는 레포야.
"열심히 하는 것"과 "같은 입력이 어디서 몇 배가 되는지 알고 배율 위에 서되, 판단력이 배율을 따라가게 하는 것"의 차이를 만드는 레포다.

## 📋 프로젝트 목표

**컨셉**: "레버리지를 빚의 동의어로 아는 것과, 자본·코드·미디어·위치·신뢰가 전부 배율 자산이며 배율에는 반드시 양면이 있음을 알고 포트폴리오로 관리하는 것은 다르다"

**핵심 차별화**:
1. 배율의 분류학 — 자본(허락 필요·관리 비용)·노동(가장 오래됨)·코드/미디어(허락 불필요·한계비용 0)·위치(병목·급소)·신뢰: 각 배율의 원천과 비용 구조(Naval 프레임의 정식화·확장)
2. 증폭의 양면 — 레버리지는 방향을 모른다: 수익률과 파산 확률의 동시 증폭(`prob`·`macro` 회수), 실수의 증폭(판단력 없는 배율의 위험)
3. 판단이 병목이다 — AI·코드 레버리지 시대에 입력(판단)의 질이 전부가 된다: **이 연구소(Phronesis Lab)의 존재 이유와 빌드 순서(L0 먼저)의 자기 증명**
4. 위치 레버리지 — 병목과 급소: `mm` 지렛대 포인트 → `moats` 이익 풀 → `geopolitics` 의존의 무기화가 같은 위치학임을 수확

**타겟 독자**:
- 노력의 양으로 승부해온 사람(배율 1배의 삶)
- 레버리지를 대출로만 이해하는 사람
- 코드·콘텐츠 자산을 갖고도 배율로 인식 못 하는 개발자
- AI 도구로 출력이 10배가 됐는데 판단이 병목이 된 걸 못 느끼는 사람
- L0~L4 전체를 "무엇에 힘을 쓸 것인가"라는 한 질문으로 압축하고 싶은 독자

## 🔗 레포 연결

**⬆️ 선행 (Synthesis는 선행이 전부다)**: `decision-theory`(옵션성 — 비대칭의 원형), `probabilistic-thinking`(Kelly·파산 — 배율의 안전 조건), `mental-models`(병목·지렛대 포인트). 이 셋 없이 읽으면 동기부여 콘텐츠가 된다.
**🤝 시너지**: `compounding-everywhere`(레버리지는 복리의 r을 사고, 파산 확률로 값을 치른다 — 두 레포의 곱이 장기 부의 방정식), `feedback-loops-everywhere`(지렛대 지점 = 루프 개입의 위치학 — 분업).
**🧬 수렴 회수처**: `pf`·`fs`(재무 레버리지·듀폰)·`ue`(영업 레버리지)·`macro`(레버리지 사이클)·`micro`(한계비용 0)·`dec`(옵션성)·`mm`(멱법칙·병목)·`moats`(이익 풀)·`negotiation`(BATNA·대체불가성)·`geo`(의존의 무기화)·`tech`(플랫폼 리스크) — **L0~L4의 레버리지 예고 전부가 이 레포로 모인다.**

## 🎯 1단계: 전체 구조 설계

> Synthesis 레포는 6챕터 체제 — 챕터가 주제가 아니라 **같은 구조가 등장하는 영역**이다.

### Chapter 1: 구조의 정식화 (4개 문서)
- 레버리지의 일반형 — 출력 = 입력 × 배율: 배율의 원천이 자산이고, 배율의 획득 비용이 가격이다
- 증폭의 양면 — 레버리지는 방향을 모른다: 이익·손실·실수·평판 훼손의 동시 증폭(이 레포의 헌법)
- 배율의 분류학 — 자본·노동·코드/미디어·위치·신뢰: 허락 필요성·관리 비용·복제 가능성의 3축 비교표
- 한계 입력의 위치학 — 같은 한 시간이 어디서 몇 배가 되나(mm 지렛대 포인트 회수): 입력 배분의 재설계 질문

### Chapter 2: 돈의 레버리지 (5개 문서)
- 재무 레버리지 — 부채의 증폭 수학 재정리(pf·fs 듀폰 회수): ROE의 세 번째 항이 하는 일과 청구서
- 레버리지 × 변동성 = 파산 — 마진콜·강제청산의 메커니즘(prob·markets 회수): 증폭이 절단을 부르는 경로(compounding 절단과 직결)
- 영업 레버리지 — 고정비 구조의 증폭(ue 회수): 매출 변동이 이익 변동으로 몇 배 확대되나, 침체에서의 역회전
- 옵션성 — 비대칭 레버리지(dec 회수): 하방 고정·상방 개방의 구조, 프리미엄이라는 가격, 레버리지의 가장 안전한 형태
- 레버리지 사이클 — 개인의 합리적 차입이 집단의 취약성으로(macro·Minsky 회수): 미시 배율의 거시 합성

### Chapter 3: 무한 복제의 레버리지 (5개 문서)
- 코드 레버리지 — 한계비용 0의 증폭(micro 회수): 한 번 작성, 무한 실행 — 소프트웨어가 세상을 먹는 수학
- 미디어 레버리지 — 잠자는 동안 일하는 콘텐츠: 이 연구소의 블로그·레포 자체가 미디어 레버리지라는 자기 참조
- 허락이 필요 없는 레버리지 — 자본(허락 필요)·노동(관리 필요)과의 결정적 차이(Naval): 개인의 시대가 열린 구조적 이유
- 멱법칙의 기원 — 레버리지가 분포를 만든다(mm 회수): 복제 비용 0 → 승자독식 → 멱법칙의 인과 사슬(tech 슈퍼스타 경제 회수)
- AI 레버리지 — 코드 레버리지의 재귀적 증폭: 출력이 10배가 될 때 판단이 병목이 되는 구조 — **Phronesis Lab의 존재 이유, 이 문서가 기관의 자기 증명이다**

### Chapter 4: 사람·조직의 레버리지 (4개 문서)
- 노동 레버리지 — 위임의 배율과 관리 비용: 가장 오래된 레버리지의 수학(대리인 비용 — incentive 회수), 위임 가능 단위의 설계
- 신뢰의 레버리지 — 신뢰가 거래 비용을 0으로(negotiation·compounding 교차): 검증 없이 움직이는 관계의 속도 배율
- 시스템·자동화 — 한 번 만든 절차의 반복 수익: SOP·자동화·템플릿의 배율 계산, 만들 가치의 손익분기(반복 횟수)
- 결정 레버리지 — 상류의 결정이 하류 전부를 지배(dec 회수): 채용·아키텍처·시장 선택 — 큰 결정에 시간을 옮기는 재배분

### Chapter 5: 위치의 레버리지 (4개 문서)
- 병목의 위치학 — 가치사슬의 급소가 이익을 가져간다(mm 병목·moats 이익 풀 회수): 같은 노력, 다른 자리, 다른 보상
- 네트워크 급소 — 의존의 무기화는 위치 레버리지의 국가 버전(geo 회수): 허브를 쥔 자의 배율, 개인·기업 번역
- 플랫폼 위의 삶 — 남의 레버리지 위에 서는 것의 양면(tech 플랫폼 리스크 회수): 배율을 빌리는 대가(정책 변경·수수료·퇴출)
- 대체 불가능성 — 희소성이 협상력의 배율(negotiation BATNA 재독): 커리어·사업의 대체재 제거 전략

### Chapter 6: 종합과 실전 (5개 문서)
- 레버리지 감사 — 내 활동·자산을 배율로 분류하는 표준 절차: 1배 노동 vs 복제 자산 vs 위치 자산의 시간 배분표(이 레포의 핵심 산출물)
- 판단이 병목이다 — 배율 시대의 입력 품질: 레버리지가 클수록 L0(판단의 운영체제)가 먼저인 이유 — **이 연구소 빌드 순서의 자기 증명**
- 안전한 레버리지의 조건 — 파산 불가 구조 + 비대칭 + 추정 오차 버퍼: Kelly·옵션성·절단 방어의 종합(prob·dec·compounding의 합류)
- 레버리지로 거짓말하는 법 — 빚으로 만든 성장의 화장·배율 숨긴 수익률 자랑(fs·crf 회수) — 방어용
- 종합 케이스 — 내 삶/사업의 레버리지 포트폴리오 재설계: 현재 배율 감사→증설 1개→위험 배율 1개 축소

→ **총 27개 문서** 목표.

## 🎨 스타일 가이드

1. **결정을 바꾸는가로 검증** — 결정을 바꾸지 못하는 지식은 잡학이다. 동기부여가 아니라 감사·재배분 절차로
2. **양면을 한 문장에** — 모든 배율 서술은 증폭의 대가(파산·실수·종속)와 한 쌍으로: 찬가 금지
3. **배율을 숫자로** — "레버리지가 크다" 금지: 몇 배인지, 비용이 얼마인지 추정한다
4. **반례에 살아남는가** — 모든 배율에 역회전 사례(레버리지 청산·플랫폼 퇴출·신뢰 붕괴)를 병기
5. **자기 참조를 활용** — 이 연구소 자체(레포=미디어 레버리지, L0 우선=판단 병목)를 사례로 쓴다: Synthesis의 자기 증명
6. 배율 분류표·비대칭 페이오프·위치 지도는 다이어그램으로

## 🔬 검증 프로토콜

> 배율 측정 + 파산 시뮬레이션 + 자기 레버리지 감사.

```python
# 환경: Python 3 + numpy (L0~L4 시뮬레이션 자산 재사용)

# 1) 레버리지 × 변동성 = 파산 (prob 자산 재사용)
#    동일 EV 전략에 레버리지 1/2/3/5배: 몬테카를로 1만 경로
#    → 기대 수익과 파산 확률의 동시 상승 곡선
#    → "최적 배율"이 존재함을 확인 (Kelly의 재림)

# 2) 영업 레버리지 측정 (ue 자산 재사용)
#    고정비 비중 30%/60%/90% 모델: 매출 ±20%의 이익 변동 배율 계산
#    → 호황의 영웅과 침체의 파산이 같은 구조임을 수치로

# 3) 콘텐츠 레버리지 실측 (살아있는 검증)
#    내 블로그/레포: 작성 시간 vs 누적 조회·유입의 시계열
#    → 시간당 산출의 배율 추정 → 소모형 활동과 비교표

# 4) 자동화 손익분기 계산
#    절차 자동화 후보 5개: 구축 시간 vs 회당 절약 × 반복 횟수
#    → 손익분기 반복 횟수 산출 → 만들 것/말 것 판정

# 5) 위치 배율의 데이터 (moats·geo 자산 재사용)
#    가치사슬 사례 1개: 단계별 이익률 분포 → 병목 단계의 배율 확인
#    → 같은 분석을 내 커리어 가치사슬에 적용

# 6) 자기 레버리지 감사 (이 레포의 산출물)
#    내 주간 시간을 배율로 분류: 1배(소모) / 복제(코드·글) / 위치 / 신뢰
#    → 분기마다 1배 비중 축소 목표 + 실수 증폭 위험(검증 절차) 점검
```

```
  └──────────┴──────────┴──────────┴──────────────┘
  → 같은 한 시간의 입력이 줄마다 다른 배율로 증폭된다
  → 현대의 전환: 코드·미디어 줄의 등장 — 허락 없이 배율을 가질 수 있다

증폭의 양면 (이 레포의 헌법):
  출력 = 입력 × 배율  — 입력의 부호를 배율은 묻지 않는다
  좋은 판단 × 10배 = 큰 성취
  나쁜 판단 × 10배 = 큰 사고 (그리고 더 빨리 온다)
  → 레버리지 사고의 절반은 "내 판단의 오류율"의 추정이다
  → 배율을 올리기 전 질문: 실수가 증폭되면 생존하는가 (절단 체크)

판단이 병목이다 (이 연구소의 자기 증명):
  AI·코드가 실행을 10배로 → 실행은 더 이상 병목이 아니다
  → 병목은 상류로 이동: 무엇을 만들지·어디에 걸지·언제 멈출지 = 판단
  → 배율의 시대에 가장 비싼 자산은 판단의 질
  → 그래서 이 연구소의 빌드 순서가 L0(판단) 먼저다 — leverage가
    Foundations의 마지막 문서가 아니라 첫 문서의 이유를 증명한다

안전한 레버리지의 3조건 (prob·dec·compounding의 합류):
  ① 파산 불가: 최악 경로에서도 원금(생존)이 지켜지는 구조
  ② 비대칭: 하방 고정·상방 개방 (옵션형 배율 우선)
  ③ 오차 버퍼: 추정이 틀려도 견디는 마진 (하프 Kelly의 정신)
  → 셋을 통과한 배율만 올린다: 통과 못 한 고배율은 빠른 파산일 뿐

판단 규칙 예시 (Principle → Boundary → Rule):
  Principle : 배율을 올리기 전에 판단의 검증 절차를 먼저 올린다 —
              레버리지는 실력의 증폭기이지 대체재가 아니다
  Boundary  : 학습 단계(실수의 비용이 수업료인 구간)에선 의도적 저배율이
              정답이다 — 작게 틀리며 판단을 키운 뒤 배율을 따라 올린다
  Rule      : 새 레버리지(차입·자동화·위임·플랫폼 의존) 도입 전에
              ①실수 증폭 시나리오 ②절단 가능성 ③회수 조건 3항을 적는다.
              그리고 분기 감사에서 1배 노동의 시간 비중을 측정해
              복제·위치 자산으로의 이전 1건을 의무화한다
```
