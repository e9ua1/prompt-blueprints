# Incentive Design Distilled 레포지토리 제작 프롬프트

나는 "Incentive Design Distilled" 레포지토리를 만들려고 해.
측정하는 순간 망가지는 이유 — Goodhart의 법칙이 작동하는 메커니즘(대리 지표와 진짜 목표의 괴리), 주인-대리인 문제에서 성과급이 리스크를 전가하는 수학, 멀티태스킹 환경에서 측정 가능한 것만 하게 되는 구조(Holmström), 메커니즘 디자인이라는 역게임이론(정직이 최선이 되게 규칙을 짜는 법), 그리고 벌금이 죄책감을 가격으로 바꿔버리는 구축 효과까지 끝까지 해부하는 레포야.
"KPI를 설정하는 것"과 "그 지표가 어떻게 게이밍될지 먼저 시뮬레이션하고 게이밍 내성이 있는 구조를 설계하는 것"의 차이를 만드는 레포다.

## 📋 프로젝트 목표

**컨셉**: "보상을 걸면 움직인다는 것과, 보상이 정확히 무엇을 움직이는지(대개 의도와 다른 것) 알고 역설계하는 것은 다르다"

**핵심 차별화**:
1. Goodhart의 메커니즘 — 지표는 목표의 대리물이고, 압력은 대리물과 목표의 틈으로 새어 나간다: 코브라 효과부터 분식회계(`fs` 약속 회수)까지 같은 구조
2. 인센티브의 3종과 구축 — 금전·사회적·도덕적 인센티브는 합산되지 않는다: 벌금이 죄책감을 밀어내는 구축 효과(어린이집 실험)의 함의
3. 메커니즘 디자인 — `game-theory`의 역방향: 원하는 균형에서 거꾸로 규칙을 설계, 유인 합치성(정직이 최선)이라는 설계 기준
4. 게이밍 내성 설계 — 짝지표(guardrail)·다면 측정·재량 결합: 완벽한 지표는 없으므로 깨지는 방식을 관리한다

**타겟 독자**:
- KPI를 도입할 때마다 예상 못 한 부작용에 당하는 창업가·팀장
- 영업 커미션이 할인 남발을 만드는 걸 보면서 원인을 사람에서 찾는 사람(`pricing` 약속 회수)
- 추천 리워드가 체리피커만 모으는 걸 겪은 그로스 담당자(`funnel` 약속 회수)
- "라인 수로 평가하면 라인 수가 늘어난다"를 겪고도 다음 지표를 또 단일 지표로 거는 개발 조직
- `mm`의 인센티브 렌즈와 측정의 역습 예고를 설계 능력으로 완성하려는 독자

## 🔗 레포 연결

**⬆️ 선행**: `game-theory-distilled`(메커니즘 디자인 = 역게임이론), `microeconomics-distilled`(주인-대리인·도덕적 해이의 뿌리).
**🤝 시너지**: `statistics-literacy-distilled`(지표의 분모·정의 — 게이밍은 통계 조작과 한 끗), `cognitive-bias-distilled`(인센티브 설계는 환경 설계의 조직 버전).

## 🎯 1단계: 전체 구조 설계

### Chapter 1: 인센티브라는 렌즈 (4개 문서)
- 행동은 구조의 함수 — 사람을 비난하기 전에 보수 구조를 심문한다(mm 렌즈의 회수): "누가 무엇으로 보상받나" 지도 그리기
- 인센티브의 3종 — 금전·사회적·도덕적: 각각의 작동 영역과 강도, 합산되지 않는 이유
- 구축 효과 — 벌금이 죄책감을 가격으로 바꾼다(어린이집 실험): 금전 보상이 내적 동기를 밀어내는 조건
- 렌즈의 한계 — "인센티브를 보여달라"(Munger)가 과잉 적용되는 곳: 정체성·습관·역량이 지배하는 영역

### Chapter 2: Goodhart의 법칙 (5개 문서)
- 법칙의 메커니즘 — 지표 = 목표의 대리물, 압력 = 틈으로 새는 물: 괴리의 유도(mm 약속의 회수)
- 게이밍의 유형학 — 노력 왜곡(쉬운 것만)·수치 조작·대상 선별(크리밍): 유형별 식별 신호
- 코브라 효과 — 인도 코브라·소련 못 공장·하노이 쥐: 보상이 공급을 창조하는 역설의 구조
- KPI 실패의 해부 — 콜센터 통화시간·검거율·병원 대기시간·테스트 커버리지: 4사례 공통 패턴 추출
- 분식회계 = KPI 게이밍 — 이익 지표 압력이 회계 선택을 비트는 경로(**fs 약속의 회수**): WorldCom을 인센티브로 다시 읽기

### Chapter 3: 주인-대리인 문제 (5개 문서)
- 문제의 정식화 — 정보 비대칭 + 이해 불일치(micro 직결): 모든 위임 관계의 공통 구조
- 성과급의 수학 — 인센티브 강도 vs 리스크 전가의 트레이드오프: 강한 성과급이 항상 답이 아닌 유도
- 멀티태스킹 문제 — 측정 가능한 일에만 노력이 쏠린다(Holmström): 측정 불가 업무가 중요할수록 약한 인센티브가 정답인 역설
- 주식·옵션 보상 — 정렬의 의도와 실제(단기주의·지표 조작 유인): 경영진 보상의 실증
- 모니터링 vs 신뢰 — 감시 비용과 신뢰 훼손의 비용 비교: 어디까지 재고 어디부터 믿나

### Chapter 4: 메커니즘 디자인 (5개 문서)
- 역게임이론 — 원하는 균형에서 거꾸로 규칙을 설계한다: 게임을 바꾸는 5손잡이의 체계화(gt 직결)
- 유인 합치성 — 정직이 최선의 전략이 되게: 2위 가격 경매의 일반화(gt Vickrey 회수)
- 자기 선택 메뉴 — pricing 티어·보험 디덕터블·난이도 선택: 메뉴가 정보를 캐는 구조(**pricing 약속의 이론적 완결**)
- 진실을 캐는 장치 — 솔로몬의 재판·분할-선택(cake cutting)·예측 시장: 거짓이 손해가 되는 설계들
- 설계의 한계 — 불가능성 정리의 직관(모든 좋은 성질을 동시에 가질 수 없다): 완벽한 메커니즘 환상의 해체

### Chapter 5: 조직의 인센티브 (6개 문서)
- 보상 설계의 축 — 개인 vs 팀, 절대 vs 상대, 단기 vs 장기: 축마다의 구조적 부작용 매트릭스
- 토너먼트로서의 승진 — 토너먼트 이론: 큰 상금의 동기 효과와 사보타주·정치의 부작용
- OKR vs KPI — 측정 철학의 차이: 도전 목표를 보상과 분리하는 것이 Goodhart 방어 장치인 구조
- 영업 커미션 설계 — 할인 권한·기간 절벽·샌드배깅의 메커니즘과 방어(**pricing 할인 통제 약속의 회수**)
- 개발 조직의 인센티브 — 라인 수·커밋 수·속도 지표의 게이밍, 장애 책임제가 은폐를 낳는 구조와 블레임리스의 설계 근거
- 비금전 설계 — 인정·자율·성장·지위: 구축 효과를 피하면서 동기를 만드는 구조

### Chapter 6: 제품·시장의 인센티브 (5개 문서)
- 추천·리워드 설계 — 체리피커와 사기 유인, 양면 보상·지연 지급·행동 조건의 방어(**funnel 약속의 회수**)
- 리뷰·평판 시스템 — 조작 유인(가짜 리뷰·보복 평점)과 설계 대응: 검증 구매·분포 공개·시간 가중
- 커뮤니티와 오픈소스 — 금전 없는 기여의 인센티브(평판·학습·소속): 돈을 넣으면 망가지는 곳(구축의 실전)
- 플랫폼의 인센티브 정렬 — 수수료 구조가 공급자 행동을 정한다: 정률 vs 정액 vs 광고의 행동 효과
- 다크 인센티브 식별 — 중독 설계·추천 알고리즘의 체류 극대화: 사용자와 플랫폼의 유인 충돌 지도(방어용)

### Chapter 7: 실전 (5개 문서)
- 인센티브 감사 — 조직·제품의 유인 지도 그리기 절차: 명시 보상·암묵 보상·처벌의 3층 점검
- 게이밍 내성 설계 — 짝지표(guardrail)·다면 측정·재량 결합·로테이션: 깨짐을 관리하는 설계 패턴
- 변경의 이행 — 인센티브를 바꿀 때의 과도기 게이밍·기득권 저항: 이행 설계의 절차
- 인센티브로 거짓말하는 법 — 지표 체리피킹·목표 후행 설정·분모 조작 — 방어용(stat 직결)
- 종합 — 실패한 KPI 1개를 진단(게이밍 경로)→재설계(내성 구조)→이행까지 풀 워크스루

## 📄 문서 구조

각 문서 10섹션 (phronesis 표준):
1. **🎯 핵심 질문** — 이 문서가 바꾸려는 결정
2. **🌍 어디서 마주치나** — 사업·일상에서 이 원리가 작동하는 장면
3. **🔍 통념** — 흔한 오해, 그 오해가 비싼 이유
4. **⚙️ 메커니즘** — 왜 그렇게 작동하는가 (유도·1차 원리)
5. **📜 사례** — 실제 세계에서 검증된 기록
6. **🔨 반례** — 깨지는 조건, 경계는 어디인가
7. **🧬 횡단 연결** — 다른 레이어에서 반복되는 같은 구조
8. **⚖️ 트레이드오프** — 이 원리를 적용하는 비용
9. **🧭 판단 규칙** — Principle → Boundary → Rule
10. **🤔 다음 질문** — 미해결 질문, 다음 문서 연결

이 레포에서 `⚙️ 메커니즘`은 보수 구조의 유도와 게이밍 경로의 사전 시뮬레이션, `📜 사례`는 KPI 실패의 실증 기록(출처 명시), `🔨 반례`는 "인센티브가 답이 아닌 곳"(역량·정체성·구축 영역), `🧭 판단 규칙`은 설계 체크리스트 형태가 중심.

## 🎨 스타일 가이드

1. **결정을 바꾸는가로 검증** — 결정을 바꾸지 못하는 지식은 잡학이다. 모든 문서는 측정·보상 구조의 구체적 변경으로 끝난다
2. **설계 전에 게이밍을 시뮬레이션** — 모든 지표 제안에 "내가 게이머라면" 사고 실험을 절차로 내장
3. **사람 비난 금지** — 게이밍은 구조의 산출물: 진단의 화살표는 항상 구조로
4. **반례에 살아남는가** — 인센티브 만능론의 경계(구축·정체성·역량)를 모든 처방에 병기
5. **완벽한 지표는 없다** — 목표는 무결점이 아니라 게이밍 내성: 짝지표와 재량의 결합을 기본형으로
6. 괴리 다이어그램·트레이드오프 곡선·유인 지도는 다이어그램으로

## 🔬 검증 프로토콜

> 게이밍 시뮬레이션 + KPI 실패 사례 데이터베이스 + 자기 조직·제품 감사.

```python
# 환경: Python 3 + 사례 수집 + 자기 프로젝트 적용

# 1) Goodhart 시뮬레이션
#    에이전트가 진짜 산출(관측 불가)과 지표(관측 가능)에 노력 배분
#    → 지표 보상 강도를 올릴수록 진짜 산출이 줄어드는 역전 구간 재현
#    → 지표-목표 상관이 높을 때/낮을 때의 차이 측정

# 2) 멀티태스킹 모형
#    측정 가능 업무 A + 측정 불가 업무 B(상호 보완)
#    → A에만 성과급: B 붕괴 → 총가치 하락의 조건 도출 (Holmström 재현)

# 3) KPI 실패 데이터베이스 (이 레포의 자산)
#    공개 사례 15건+: 지표·의도·게이밍 경로·결과·출처 표준 양식 수집
#    → 게이밍 유형(왜곡/조작/선별) 라벨링 → 패턴 빈도표

# 4) 추천 리워드 역선택 시뮬레이션
#    진성 사용자 vs 체리피커 혼합 모집단에 보상 설계 3종
#    (즉시 현금 / 지연 지급 / 행동 조건부) → 획득 질의 차이 측정

# 5) 토너먼트 부작용 시뮬레이션
#    상대평가 보상 + 사보타주 옵션이 있는 에이전트
#    → 상금 격차가 커질수록 협력 붕괴가 시작되는 임계 탐색

# 6) 자기 감사 (살아있는 검증)
#    내 프로젝트/조직의 지표 3개: "내가 게이머라면" 공격 시나리오 작성
#    → 짝지표 설계 → 실제 운영 후 게이밍 발생 여부 추적
```

```
        │                                  │
        └── 보상 압력이 걸리면 ──→ 지표만 최적화 (전화 끊기)
  → 압력 강도 × 괴리 크기 = 게이밍의 양
  → 처방 1: 괴리를 줄인다 (더 나은 지표)
  → 처방 2: 압력을 줄인다 (보상-지표 분리, OKR의 본질)
  → 처방 3: 틈을 감시한다 (짝지표·재량)

성과급의 트레이드오프 (강할수록 좋지 않다):
  인센티브 강도 ↑ → 동기 ↑, 그러나
   ① 리스크 전가 ↑ (운에 좌우되는 보상 → 위험 프리미엄 요구)
   ② 측정 가능 업무로 왜곡 ↑ (멀티태스킹)
   ③ 게이밍 유인 ↑
  → 최적 강도 = 측정 정확도와 업무 단순성의 함수
  → 측정이 나쁜 복잡 업무(개발·연구)일수록 약한 인센티브 + 좋은 채용이 정답

구축 효과 (3종 인센티브는 합산되지 않는다):
  어린이집 지각 벌금 도입 → 지각 증가 (벌금 = 죄책감의 가격표)
  벌금 철회 → 지각률 안 돌아옴 (도덕적 인센티브는 한 번 밀려나면 복구 난망)
  → 금전 보상은 사회적·도덕적 동기를 대체하지 보완하지 않는 경우가 있다
  → 자원봉사·기여·헌혈·오픈소스에 돈을 넣기 전에 멈춰라

게이밍 내성의 기본형 (완벽한 지표는 없다):
  주지표: 속도 (배포 빈도)
  짝지표: 품질 (장애율) ← 주지표 게이밍이 새어 나올 자리를 지킨다
  + 재량: 정성 평가 결합 (지표가 못 보는 것의 보험)
  + 로테이션: 지표의 수명 관리 (게이밍이 학습되기 전에 갱신)
  → 설계 질문: "이 지표를 망가뜨리는 가장 쉬운 방법은?"을 먼저 적는다

판단 규칙 예시 (Principle → Boundary → Rule):
  Principle : 지표에 보상을 걸기 전에 게이밍 경로를 먼저 설계 문서에 적는다
  Boundary  : 단순·단기·측정 정확 업무(단순 영업·생산량)에선 강한
              단일 지표 성과급이 실제로 잘 작동한다 — 복잡 업무의 규칙을
              과잉 일반화하지 않는다
  Rule      : 새 KPI 제안서에는 ①목표와 지표의 괴리 ②예상 게이밍 3경로
              ③짝지표 ④폐기 조건을 필수 항목으로 요구한다. 넷 중 하나라도
              비어 있으면 보상 연동 없이 관찰 지표로만 시작한다
```
