# Copy & Narrative Distilled 레포지토리 제작 프롬프트

나는 "Copy & Narrative Distilled" 레포지토리를 만들려고 해.
글이 행동을 만드는 메커니즘 — 헤드라인이 왜 본문의 5배 무게인지, 구체가 추상을 이기는 인지적 이유, 스토리가 반론을 끄는 서사 운송의 구조, 미끄럼틀처럼 모든 문장이 다음 문장을 읽게 만드는 설계, 그리고 빼기가 더하기인 편집의 기술까지 끝까지 해부하는 레포야.
"글을 잘 쓰는 것"과 "독자의 인지 부하를 낮추고 다음 행동으로 미끄러뜨리는 구조를 설계하는 것"의 차이를 만드는 레포다.

## 📋 프로젝트 목표

**컨셉**: "문장력을 기르는 것과, 글의 목적이 행동이라는 전제에서 주목→이해→설득→행동의 구조를 설계하는 것은 다르다"

**핵심 차별화**:
1. 명료함의 경제학 — 인지 부하 = 이탈 비용: 읽기 쉬움은 문체 취향이 아니라 전환율 변수라는 정량 관점
2. 구조가 문장을 이긴다 — 고치는 순서는 아이디어→구조→문장: 헤드라인·리드·미끄럼틀이라는 구조물의 설계가 8할
3. 스토리의 메커니즘 — 서사 운송(narrative transportation)이 반론 생성을 억제하는 인지 구조(`persuasion` Ch4의 문장 구현), 상황-갈등-해결의 실용 축약
4. 테스트가 심판 — 카피의 좋고 나쁨은 취향이 아니라 A/B 데이터(`funnel`의 절차 적용), 직감 논쟁의 종결 장치

**타겟 독자**:
- 제품은 좋은데 랜딩 페이지가 그 가치를 전달 못 하는 개발자 창업가
- 헤드라인에 5분, 본문에 5시간을 쓰는 사람(거꾸로다)
- 기능 나열은 하는데 "그래서 뭐가 좋은데"에 답 못 하는 글을 쓰는 사람
- 기술 블로그를 쓰지만 읽히지 않는 개발자
- `persuasion`의 원리를 문장 단위 실행으로 옮기려는 독자

## 🔗 레포 연결

**⬆️ 선행**: `persuasion-psychology-distilled`(설득의 메커니즘 — 카피는 그 문장 구현체).
**🤝 시너지**: `positioning-brand-distilled`(포지셔닝이 메시지의 내용을, 카피가 형태를 정한다), `funnel-growth-distilled`(카피의 심판은 A/B).
**🧬 수렴**: `negotiation-distilled`(서면 협상·제안서는 카피의 대면 버전), `statistics-literacy-distilled`(데이터 스토리텔링의 정직성 경계), `copy의 원리는 L4 역사 서술·L5 문서화에도 재등장한다`.

## 🎯 1단계: 전체 구조 설계

### Chapter 1: 글이 일하게 하라 (4개 문서)
- 카피 vs 문학 — 목적이 행동인 글의 규칙은 다르다: 아름다움이 아니라 명료함·추진력
- 명료함의 경제학 — 인지 부하와 이탈의 관계, "읽기 쉬움"을 전환율 변수로 보는 관점
- 한 가지 아이디어 — one big idea 원칙: 두 개를 말하면 0개가 전달된다, 아이디어 선별 절차
- 독자 우선 — 자랑(우리는)과 혜택(당신은)의 변환, "So what?" 테스트의 기계적 적용

### Chapter 2: 주목의 구조 (5개 문서)
- 헤드라인의 수학 — 5배 법칙(읽는 사람의 비대칭), 시간 배분을 거꾸로 잡아야 하는 근거
- 헤드라인의 원리 — 호기심 갭·구체성·자기 관련성·뉴스성: 패턴이 아니라 원리로, 남용의 경계
- 리드 — 첫 문단의 단 하나의 일: 두 번째 문단을 읽게 하는 것, 리드 유형과 선택
- 미끄럼틀 구조 — 모든 문장의 목적은 다음 문장(Sugarman), 추진력 점검 절차
- 주목의 윤리 — 클릭베이트의 경계: 약속과 이행의 격차가 신뢰를 태운다(persuasion Ch1 기준 적용)

### Chapter 3: 설득의 문장 (5개 문서)
- 구체가 이긴다 — 추상↔구체 사다리: 주장은 추상으로, 증명은 구체로 오르내리는 기술
- 증거의 배치 — 주장→증거→의미의 단위 구조, 후기·숫자·데모의 배치(persuasion 사회적 증거의 글 버전)
- 손실과 이득의 언어 — 프레이밍의 카피 적용(bias 직결), 어느 프레임을 언제 쓰나
- 반론 선제 처리 — 독자 머릿속의 "그런데…"에 미리 답하기(inoculation의 문장 구현), 반론 수집법
- CTA 설계 — 행동 비용을 낮추는 문구·위치·단계화, "다음 한 걸음"의 원칙

### Chapter 4: 스토리의 구조 (6개 문서)
- 스토리가 작동하는 이유 — 서사 운송: 이야기에 실려 가면 반론 생성이 줄어든다(persuasion 약속의 회수), 정보 vs 의미
- 보편 구조 — 상황-갈등-해결: 모든 스토리 프레임워크의 최소 공배수, 실용 축약
- 고객이 주인공 — 브랜드는 가이드라는 역할 배정(StoryBrand), 주인공 자리를 탐내는 실패
- 갈등과 구체성 — 밋밋한 스토리의 사인은 갈등 부재: 장애물·의심·실패의 배치
- 창업 서사 — 같은 회사, 세 가지 컷: 투자자(시장·필연)·채용(미션·성장)·고객(문제·공감)
- 데이터 스토리텔링 — 숫자에 서사 입히기와 왜곡의 경계(stat 그래프 거짓말 직결), 정직한 극화

### Chapter 5: 편집의 기술 (4개 문서)
- 빼기가 더하기다 — 초고 30% 감량 규칙, 삭제 우선순위(형용사→부사→중복 주장)
- 문장 수술 — 수동태·명사화·이중 부정 제거의 인지적 이유, 동사가 일하게 하라
- 리듬과 호흡 — 문장 길이 변주의 효과, 단문의 타격과 장문의 흐름
- 가독성 측정 — 음독 테스트·가독성 지표의 활용과 한계, 한국어 가독성의 변수

### Chapter 6: 포맷별 실전 (4개 문서)
- 랜딩 페이지 — 스크롤의 서사 구조(히어로→문제→해결→증거→CTA), 섹션별 일과 순서(funnel 직결)
- 이메일·뉴스레터 — 제목 = 헤드라인의 법칙, 1:1 톤의 힘, 오픈→클릭의 이중 퍼널
- 기술 글쓰기 — 개발자의 README·블로그·문서: 정확성과 명료함의 균형, 코드와 산문의 배치
- 소셜·쇼트폼 — 첫 1초의 훅, 플랫폼 문법과 원리의 분리(문법은 변해도 원리는 남는다)

### Chapter 7: 실전 (4개 문서)
- 카피 진단 체크리스트 — 고치는 순서: 아이디어→구조→문장, 순서를 어기면 화장만 고친다
- 카피 테스트 — A/B로 검증하는 절차(funnel의 통계 적용), 테스트 가능한 가설로 쪼개기
- 카피로 거짓말하는 법 — 과장·암시·체리피킹 후기·가짜 긴급 — 방어용 카탈로그(윤리 경계 재확인)
- 종합 — 실제 랜딩 페이지 1개를 진단→구조 재설계→리라이트→테스트 설계까지 풀 워크스루

→ **총 32개 문서** 목표.

## 📄 문서 구조

각 문서 10섹션 (phronesis 표준):
1. **🎯 핵심 질문** — 이 문서가 바꾸려는 결정
2. **🌍 어디서 마주치나** — 사업·일상에서 이 원리가 작동하는 장면
3. **🔍 통념** — 흔한 오해, 그 오해가 비싼 이유
4. **⚙️ 메커니즘** — 왜 그렇게 작동하는가 (유도·1차 원리)
5. **📜 사례** — 실제 세계에서 검증된 기록
6. **🔨 반례** — 깨지는 조건, 경계는 어디인가
7. **🧬 횡단 연결** — 다른 레이어에서 반복되는 같은 구조
8. **⚖️ 트레이드오프** — 이 원리를 적용하는 비용
9. **🧭 판단 규칙** — Principle → Boundary → Rule
10. **🤔 다음 질문** — 미해결 질문, 다음 문서 연결

이 레포에서 `⚙️ 메커니즘`은 인지 부하·서사 운송의 근거와 비포/애프터 대조문, `📜 사례`는 전설적 카피와 실측 데이터가 있는 사례, `🔨 반례`는 "원리가 깨지는 맥락"(럭셔리의 모호함, 기술 문서의 호기심 갭 금지)이 중심. **모든 문서에 비포/애프터 예문 1쌍 이상 필수.**

## 🎨 스타일 가이드

1. **결정을 바꾸는가로 검증** — 결정을 바꾸지 못하는 지식은 잡학이다. 모든 원리는 리라이트 가능한 절차로
2. **이 레포 자체가 증명이다** — 레포의 모든 문서가 자기 원리를 따른다: 명료·구체·미끄럼틀(자기 위반은 버그)
3. **비포/애프터가 본체** — 원리 설명보다 대조 예문이 가르친다, 한국어 예문 우선
4. **반례에 살아남는가** — 모든 기법에 깨지는 맥락 명시
5. **취향 논쟁 금지** — 의견이 갈리면 테스트로 보내는 절차를 명시한다
6. 미끄럼틀·사다리·랜딩 구조는 다이어그램으로

## 🔬 검증 프로토콜

> 리라이트 전후 대조 + 자기 글 A/B + 스와이프 파일 역분해.

```python
# 환경: 자기 블로그/프로젝트(실험장) + 간단 측정 도구

# 1) 헤드라인 5배 법칙 자기 검증
#    내 블로그 글들의 제목별 유입/체류 데이터 수집
#    → 제목 변경 전후(또는 A/B) 클릭률 변화 측정

# 2) 리라이트 표준 과제
#    챕터마다 실제 못 쓴 카피 1개(수집) → 원리 적용 리라이트
#    → 비포/애프터를 제3자 n명에게 블라인드 선택시켜 기록

# 3) 가독성 정량화
#    문장 길이 분포·수동태 비율·명사화 빈도 측정 스크립트
#    → 리라이트 전후의 수치 변화 (감량률·평균 문장 길이)

# 4) 스와이프 파일 역분해
#    잘 작동한 랜딩/이메일 20개 수집 → 구조 라벨링
#    (히어로 유형·증거 배치·CTA 위치) → 패턴 빈도표

# 5) 미끄럼틀 점검 절차화
#    내 글 1개: 문장마다 "다음 문장을 읽게 하는가" 판정 마킹
#    → 추진력이 끊기는 지점의 유형 분류 (이탈 지점의 해부)

# 6) 데이터 스토리 정직성 체크
#    내가 쓴 숫자 포함 글: stat 레포의 왜곡 체크리스트 통과 여부 감사
```

## 💡 핵심 분석 대상

```
주목의 깔때기 (시간 배분을 거꾸로):
  헤드라인을 읽는 사람  100
  리드까지 읽는 사람     40
  본문까지 읽는 사람     20
  CTA에 도달하는 사람    10
  → 단어당 영향력은 위가 압도적인데, 작성 시간은 아래에 몰린다
  → 규칙: 작성 시간 배분 = 헤드라인 30% / 리드 20% / 구조 30% / 본문 20%

추상↔구체 사다리 (오르내림의 기술):
  추상(원리)  "복리는 시간이 만든다"          ← 의미를 준다
     ↕
  구체(사실)  "월 50만원, 25살 시작과 35살 시작의
              60살 차이는 4.1억이다"          ← 믿음을 준다
  → 추상만: 뜬구름 / 구체만: 그래서 뭐?
  → 좋은 글은 사다리를 오르내린다 — 주장(추상)마다 증거(구체) 한 칸

서사 운송 (스토리가 반론을 끄는 구조):
  논증 모드: 주장 수신 → 반론 생성 → 평가 (System 2 가동)
  서사 모드: 이야기에 탑승 → 인지 자원이 따라가기에 소진
            → 반론 생성 억제 → 결론이 스며든다
  → 강력한 만큼 위험하다: 사기의 무기이기도 (윤리 경계 필수)
  → 사용 규칙: 스토리로 열고, 검증 가능한 증거로 닫는다

고치는 순서 (화장 금지의 원칙):
  1. 아이디어: 말할 가치가 있는 하나인가 (아니면 문장을 고쳐도 무용)
  2. 구조: 헤드라인→리드→미끄럼틀이 서 있는가
  3. 문장: 그 다음에야 수동태·부사·리듬
  → 대부분의 "카피 고쳐줘"는 3을 요청하지만 문제는 1·2에 있다

판단 규칙 예시 (Principle → Boundary → Rule):
  Principle : 카피의 우열은 취향이 아니라 측정으로 판정한다
  Boundary  : 트래픽이 통계적 판정에 못 미치는 초기(stat 검정력 미달)엔
              측정 대신 원리 체크리스트와 소수 정성 테스트로 대체한다
  Rule      : 카피 의견이 갈리면 토론을 10분에서 끊고 A/B 백로그에
```
